## 클로드에게 뭔가를 시키는 두 가지 방법

클로드에게 무언가를 시키는 방법은 크게 두 가지다. 하나는 항상 지켜야 할 규칙, 다른 하나는 필요할 때만 부르는 도구다.

이 구분이 중요한 이유는 클로드가 한 번에 기억하는 양이 제한돼 있어서다. 모든 것을 항상 읽게 만들면 정작 사용자가 시킨 작업에 쓸 공간이 모자란다.

그래서 규칙은 `CLAUDE.md` 파일에 적어두고 도구는 스킬이라는 형태로 관리한다. 규칙은 세션이 시작될 때 무조건 읽힌다. 스킬은 설명 한 줄만 상시 로드되고 본문은 호출될 때 비로소 펼쳐진다.

| | 상시 | 호출 |
|---|---|---|
| 무엇 | `CLAUDE.md` | 스킬, 서브에이전트, 슬래시 명령 |
| 언제 읽히나 | 세션 시작 때 무조건 | 트리거될 때만 |
| 비용 | 매 세션 부담 | 안 부르면 없음 |

여기서 실전 규칙이 하나 나온다. 스킬이 안 불려 나오면 대개 본문이 아니라 **설명(description)이 부실한 것**이다. 본문을 고칠 게 아니라 설명에 트리거 문구를 더 넣어야 한다.

## 어디에 두면 어디까지 읽히나

`CLAUDE.md` 파일의 적용 범위는 파일을 어디에 두느냐가 정한다. 홈 폴더 아래 `.claude` 디렉토리에 두면 모든 작업에 적용된다. 특정 프로젝트 폴더에 두면 그 폴더와 하위 폴더에만 적용된다. 클로드는 현재 작업 중인 폴더에서 상위로 거슬러 올라가며 이 파일들을 찾고 하나의 지침으로 합친다. 덮어쓰기가 아니라 누적이다.

```
~/.claude/CLAUDE.md          →  모든 폴더 (전역)
~/work/myproject/CLAUDE.md   →  myproject 와 그 하위 전부
~/work/other/                →  myproject 규칙 안 읽힘
```

문체나 말투처럼 나 자신에 관한 것은 전역에, 폴더 구조나 작업 절차처럼 특정 업무에 관한 것은 프로젝트에 두는 편이 바람직하다.

> **고친 뒤에는 새 세션에서 반영된다.** `CLAUDE.md`는 세션 시작 때 한 번 읽고 만다. 수정했으면 창을 새로 열어야 한다.

## 설치

이 저장소의 규칙을 모든 작업에 적용하려면 전역 위치에 놓는다.

```bash
mkdir -p ~/.claude
curl -fsSL https://raw.githubusercontent.com/sangwonkim98/prompt/main/CLAUDE.md \
  -o ~/.claude/CLAUDE.md
```

이미 `~/.claude/CLAUDE.md`가 있다면 덮어쓰기 전에 확인할 것. 내용을 합치고 싶으면 직접 편집한다.

특정 프로젝트에만 적용하려면 그 폴더에 복사한다.

```bash
curl -fsSL https://raw.githubusercontent.com/sangwonkim98/prompt/main/CLAUDE.md \
  -o ./CLAUDE.md
```

## 규칙 요약

### 응답 방식
사용자가 지시나 요청을 하면 실행하기 전에 이해한 바를 먼저 확인받는다. 확인 전에는 실행하지 않는다. 단순 확인, 조회, 짧은 설명, 가벼운 문장 다듬기는 확인을 생략할 수 있다.

Claude와 ChatGPT 모두 이 원칙을 공유한다. 다만 각 앱의 성격에 맞게 표현만 조금 다르다.

### 문체 8조
- 대시로 부가설명 잇지 않기
- `~를 통해`, `~에 대해`, `~에 있어서` 남발 지양
- 이중 피동 `~되어진다` 지양
- 결산 어휘 3회 초과 반복 금지
- 의의 과장 금지
- `~할 수 있다` 남발 지양, 단언 가능하면 단언
- `~것이다` 연속 반복 지양
- 볼드·따옴표 과용 지양

전문은 [`COMMON.md`](COMMON.md)에 있다.

## humanize-korean 스킬과 같이 쓰기

이 저장소의 프롬프트는 예방에 해당한다. 클로드가 글을 쓰는 동안 문체를 교정해 애초에 AI 티가 나지 않게 한다. 반면 [humanize-korean](https://github.com/epoko77-ai/im-not-ai) 스킬은 치료 쪽이다. 이미 쓴 글에서 70개의 패턴을 진단하고 다시 쓴다. 둘은 충돌하지 않고 서로 보완한다.

| | 이 프롬프트 | humanize 스킬 |
|---|---|---|
| 언제 | 글을 **쓰는 동안** | 글이 **이미 있을 때** |
| 대상 | 클로드가 쓰는 글 | 아무 글이나 (GPT 글, 남의 글 포함) |
| 방식 | 상시 규칙 | 호출 |

스킬 설치는 저쪽 저장소의 안내를 따른다. 설치 후 새 세션에서 이렇게 쓴다.

```
/humanize-korean
{다듬을 텍스트}

장르: 칼럼
```

옵션은 자연어로 뒤에 붙인다. `--strict`는 정밀 모드(진단 → 윤문 → 검수 3단계), `가볍게`는 최소 개입이다.

> **주의할 점이 하나 있다.** humanize 스킬은 `CLAUDE.md`를 의도적으로 읽지 않게 설계했다. 그래서 사용자의 문체 규칙은 윤문 결과물에는 적용되지 않는다. 버그가 아니다. 남의 글을 윤문할 때 사용자 취향이 원문을 덮어쓰지 않게 하려는 설계적 판단이다.

## 모바일에서 쓰기

모바일 환경에서는 `CLAUDE.md`나 스킬을 쓸 수 없다. 대신 각 앱이 제공하는 사용자 지정 지침 기능으로 같은 문체 규칙을 적용할 수 있다.

| 앱 | 넣는 곳 |
|---|---|
| ChatGPT | 설정 → 개인 맞춤 설정 → 사용자 지정 지침 |
| Claude | 설정 → 프로필 → 개인 설정<br>또는 프로젝트별 지침 |

Claude에는 [`CLAUDE.md`](CLAUDE.md)를 쓴다.

ChatGPT나 PC GPT에는 [`CHATGPT.md`](CHATGPT.md)의 축약 프롬프트를 넣는다.

글자 수 제한이 있는 앱에서는 이 축약본을 쓴다.

```
한국어로 답할 때 문체 규칙:
대시로 부가설명 잇지 말 것(쉼표·괄호·문장분리로).
"~를 통해/~에 대해/~에 있어서" 남발 금지, 조사로 직결.
이중피동 "~되어진다" 금지.
"결론적으로/따라서/이를 통해" 3회 초과 반복 금지.
"시사하는 바가 크다/주목할 만하다" 류 의의 과장 금지.
"~할 수 있다" 남발 금지, 단언 가능하면 단언.
"~것이다" 연속 반복 금지.
볼드·따옴표는 정말 강조할 곳에만.
```
